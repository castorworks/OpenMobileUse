# Open Mobile Use 1.0 技术方案

**方案日期**　2026-11-19

**状态**　待实现。1.0 正式支持的目标平台为 Android、原生鸿蒙（HarmonyOS）和 iOS。三个平台各至少一台真机通过验收后发布。

Open Mobile Use 让开发者从 Mac 观察和操作自己已授权的手机。首版交付一个本地命令行工具 `omu`。用户可以单步操作、运行固定脚本，也可以为带有验收条件的目标启用可选的 Agent 模式。首个发布场景是打开系统设置、找到蓝牙页面、确认已到达，再回到设置首页。整个流程保留用户原有的蓝牙状态。

## 1. 支持范围与现有设备

1.0 以 macOS 为控制端，三个平台均通过 USB 做发布验收。设备支持清单以实际通过验收的型号、系统构建和工具链组合为准。

| Android 真机，型号待定 | 本机 Android SDK 已安装 Platform-Tools 37.0.0。本次运行 `adb devices -l` 返回 0 台设备 | 接入一台允许 USB 调试的真机，记录型号、Android 版本、API 级别和厂商系统构建，验证驱动安装、设置导航和完整控制流程 |
| 鸿蒙 BRA-AL00，系统构建 7.0.0.111，API 26 | 本机 DevEco Studio 内含 HDC 3.2.0d。通过 USB 已读到设备信息，机上 UITest 7.0.0.1 的帮助列出了 `screenCap`、`dumpLayout` 和 `uiInput` | 实际回读截图和控件树，验证点按、滑动、中英文输入以及断线后的恢复 |

- **iOS** 通过 USB 信任 Mac，启用开发者模式及 UI 自动化，使用可为该设备签名的开发团队配置 WDA。[Appium 真机准备](https://appium.github.io/appium-xcuitest-driver/latest/getting-started/device-setup/) · [Appium 签名配置](https://appium.github.io/appium-xcuitest-driver/latest/getting-started/provisioning-profile/)

## 2. 用户可以做什么

| 能力 | 1.0 的可观察结果 |
| --- | --- |
| 发现与诊断 | 列出设备、平台、连接方式。对指定设备区分“已发现”和“可控制”，指出故障发生在连接、授权、签名还是自动化会话 |
| 查看屏幕 | 获取当前屏幕的 PNG、截图尺寸与方向。按需获取控件树，展示可用的文字、标识、角色和边界 |
| 操作界面 | 按标识或可见名称点按控件，也可按截图位置点按、滑动。在普通可编辑输入框输入中英文 |
| 打开与导航 | 启动指定的已安装 App，三个平台都提供系统设置入口。Android 和鸿蒙可执行系统返回动作，iOS 使用当前页面的导航按钮 |
| 执行与验证 | 运行有序步骤，等待指定控件出现或消失。返回失败步骤、错误原因、耗时和退出码，供调用者判断任务结果 |
| 按目标操作 | 用户选择模型和任务。Agent 根据当前界面逐步选择动作，主机根据设备证据报告已完成、需要人工处理或失败 |

1.0 使用按需截图和本地设备连接。脚本可完全离线运行。Agent 模式复用相同的设备接口；使用云模型时，仅将本次任务允许发送的观察交给用户选择的服务。实时投屏留待人工远控场景再设计。

## 3. 结构与会话

主机工具采用 TypeScript 和 Node.js。Android 和 iOS 共用只监听本机回环地址的 Appium 服务，分别加载 UiAutomator2 和 XCUITest 驱动。鸿蒙适配器直接调用本机 HDC。设备工具路径、iOS 签名团队和应用入口映射由本机配置提供。发行时记录通过真机验收的依赖版本。

| 模块 | 职责与接口 | 状态与产物 |
| --- | --- | --- |
| CLI 与脚本执行器 | 解析命令和脚本，逐步执行，统一超时、退出码和 JSON 输出 | 按用户指定的目录写入截图、控件树或运行报告 |
| Agent 运行器与模型适配器 | 运行器持有设备会话和动作预算；模型适配器接收目标、观察和近期步骤，返回一个动作、完成提议或求助 | 运行中保留最新观察和必要的步骤摘要；模型凭据由主机管理 |
| 任务验证器 | 从用户选定的任务定义加载有序验收条件，直接核对设备观察及已执行动作 | 只记录满足条件的观察编号、读数和检查结果；由运行器据此生成终态 |
| 设备与会话管理 | 枚举设备，按平台和设备 ID 路由，为一次命令或整个脚本取得设备独占锁 | 会话绑定一台设备。锁随进程退出释放；同机并发操作返回 `DEVICE_BUSY` |
| Android 适配器 | 通过 ADB 枚举设备，以序列号设置 `appium:udid`，创建 UiAutomator2 会话 | 同一脚本复用会话；并行真机会话各自分配 `systemPort`，退出时关闭会话并释放端口 |
| 鸿蒙适配器 | 调用 `hdc -t <目标>` 获取设备能力，执行观察、输入和应用启动 | 截图和布局使用各次操作独立的设备临时文件，取回后清理 |
| iOS 适配器 | 创建、复用和关闭绑定目标 UDID 的 WebDriver 会话，执行元素查询和手势 | 同一脚本复用一个会话。WDA 签名材料由 Xcode 管理 |

### 三个平台的动作映射

| 动作 | Android | 鸿蒙 | iOS |
| --- | --- | --- | --- |
| 截图、读取控件 | WebDriver 获取 PNG 和 UiAutomator2 布局 XML，读取资源 ID、文本、内容描述和边界 | `uitest screenCap` 和 `dumpLayout`，通过 HDC 取回 PNG 和布局 JSON | WebDriver 截图和 page source，从 XCUITest 元素属性读取类型、名称、值和边界 |
| 按控件点按 | 按资源 ID、文本或内容描述唯一匹配控件，调用元素点击 | 在最新布局中唯一匹配目标，将其可见边界中心换算为 `uiInput click` 的坐标 | 唯一匹配原生元素，调用元素点击 |
| 按位置点按、滑动 | 将截图位置换算为当前显示区域坐标，通过 WebDriver 触摸动作执行 | 将起止位置换算成当前屏幕像素，调用 `uiInput click/swipe` | 将起止位置换算成当前方向的逻辑坐标，使用 XCUITest 手势 |
| 文本输入 | 聚焦可编辑元素并使用 WebDriver 元素输入，以控件回读值验证中文和符号 | 定位并聚焦输入框，按设备支持情况调用 `uiInput text` 或 `inputText` | 聚焦可编辑元素，通过 WebDriver 输入文本 |

## 4. 命令与脚本约定

以下为拟实现的调用方式。`devices` 返回可用于后续命令的设备 ID。每个操作必须指定目标设备，避免多机连接时误操作。

```sh
omu devices --json
omu doctor --device <设备ID>
omu inspect --device <设备ID> --output ./capture
omu tap --device <设备ID> --label "蓝牙"
omu run --device <设备ID> --script ./settings-bluetooth.json --json
omu agent --device <设备ID> --task settings.bluetoothRoundTrip --model <已配置的模型> --json
```

`inspect` 将全屏 PNG 和标准化控件树写到指定目录。一次观察带有设备 ID、观察时间、屏幕方向和截图尺寸。截图和树是顺序采集的；采集期间若方向或前台应用发生变化，应重新观察。受保护画面和无法读取的控件返回实际可用的部分与原因。

脚本带有 `schemaVersion: 1`。以下示例在三台验收机上使用同一份文件，起始状态为简体中文的设置首页。`route` 引用按平台和机型维护的有限步骤列表，每步使用既有的点击、滑动、返回或等待动作。例如蓝牙入口在二级菜单的 Android 机型，进入路径会多点一级菜单，返回路径也要多退一级。`bluetooth.pageMarker` 指目标页独有的可见控件，通过观察它验证到达。

```json
{
  "schemaVersion": 1,
  "steps": [
    { "action": "launchApp", "app": "settings" },
    { "action": "waitFor", "target": "settings.homeMarker", "state": "visible", "timeoutMs": 5000 },
    { "action": "route", "name": "settings.toBluetooth" },
    { "action": "waitFor", "target": "bluetooth.pageMarker", "state": "visible", "timeoutMs": 5000 },
    { "action": "route", "name": "bluetooth.toSettingsHome" },
    { "action": "waitFor", "target": "settings.homeMarker", "state": "visible", "timeoutMs": 5000 }
  ]
}
```

- **元素定位。** 选择器支持平台标识 `id`、可见名称 `label` 和可选角色 `role`。名称采用精确匹配。零个匹配返回未找到，多个匹配返回歧义及候选摘要。同一个逻辑目标允许配置平台专用选择器，例如鸿蒙设置列表中的文字和 iOS 中包含该文字的单元格。
- **坐标。** 位置动作接收相对完整截图的归一化坐标，左上角为原点，两个轴的取值均为 0 到 1。适配器负责方向、缩放和逻辑点换算。调用者引用的观察已因旋转或窗口变化而失效时返回 `STALE_OBSERVATION`，提示重新定位。
- **结果。** 每步返回动作名、状态和耗时。运行报告包含平台、目标设备、首个失败步骤和错误码。进程退出码约定为 0 成功、1 执行失败、2 参数或脚本无效。动作成功表示驱动接受了操作；页面是否到达由后续 `waitFor` 验证。

## 5. Computer Use 与手机 Agent 调研

以下对照基于 2026-11-19 查阅的官方协议和三个开源手机 Agent 的指定源码版本。厂商两行描述的是由客户端执行动作的 Computer Use 接口。手机项目各自的运行环境和评测条件不同，本次没有进行真机性能或成功率对比。

| 方案 | 怎样观察屏幕、决定下一步 | 何时结束、如何判断成功 |
| --- | --- | --- |
| OpenAI Computer Use（Responses API） | 客户端将屏幕截图交给模型。模型用 `computer_call` 提出一个或一组动作，客户端执行后用对应的 `call_id` 回传含新截图的 `computer_call_output` | 这一轮没有新的计算机调用时，调用方仍要区分最终答复、求助和其他工具调用。指南要求在应用里核对最终结果。[OpenAI 工具循环](https://developers.openai.com/api/docs/guides/tools-computer-use) |
| Anthropic Computer Use | Claude 请求截图、点击、输入等工具；客户端执行后，按 `tool_use_id` 为每个调用返回结果。一批动作结束时可以附上新截图，供下一轮定位 | `tool_use` 要求继续处理；`end_turn` 表示模型结束本轮，达到 token 限额等停止原因另行处理。协议没有为手机业务目标定义成功条件。[Computer Use 工具](https://platform.claude.com/docs/en/agents-and-tools/tool-use/computer-use-tool) · [停止原因](https://platform.claude.com/docs/en/agents-and-tools/tool-use/how-tool-use-works) |
| Open-AutoGLM（PhoneAgent） | 每步获取截图、尺寸和前台 App，把目标或上一步历史交给模型，解析并派发动作。旧截图从历史消息中移除 | `finish` 或执行器的终止标记会结束循环，达到步数上限也会退出。该版本还会把部分解析异常转为 `finish`。这说明实现时需要分别记录停止原因与验证结果。[主循环与动作解析](https://github.com/zai-org/Open-AutoGLM/blob/86f55382982fb054e8fc98ca80609dff8a2cdc3c/phone_agent/agent.py#L94-L239) |
| Mobile-Agent-v2 | 从截图提取 OCR 文字、图标和位置；结合历史动作与已完成子目标选择下一步。启用反思时，再对照操作前后的画面，判断是否进入预期页面 | 动作模型给出 `Stop` 即退出。前后画面对照用于发现点错或无进展，当步的反思结果只说明该步效果。[感知、决策与停止分支](https://github.com/X-PLUG/MobileAgent/blob/c4cd0a8f9ddedad24dd8a3daf3a56ca69343849f/Mobile-Agent-v2/run.py#L174-L426) |
| AndroidWorld 的 M3A Agent | 在原图外提供带元素编号的截图、控件描述和历史。模型按编号或位置操作，通过操作前后的观察总结这一步 | M3A 可以报告 `complete` 或 `infeasible`。AndroidWorld 的任务评测另有独立检查，例如蓝牙任务读取环境中的系统状态并与期望值比较。这种评测读取方式依赖 Android 环境。[M3A](https://github.com/google-research/android_world/blob/55ddaf5edc6f6c25673aed343907d5b9dca66f84/android_world/agents/m3a.py) · [蓝牙验证器](https://github.com/google-research/android_world/blob/55ddaf5edc6f6c25673aed343907d5b9dca66f84/android_world/task_evals/single/system.py#L211-L230) |

## 6. 三个平台共用的 Agent 模式

**任务入口。** `omu run` 照脚本执行。`omu agent` 接受已登记的任务，任务定义包含自然语言目标、允许进入的 App、允许的动作、验收条件和预算。模型看到目标与观察，自行选择中间步骤。蓝牙任务只开放设置内的导航操作。验收时不给模型脚本里的固定往返路径，才能测到它根据屏幕选择下一步的能力。

### 观察与定位

一次观察有唯一的 `observationId`。主机同时提供截图尺寸、方向、前台 App、可交互元素和采集状态。Android 从 UiAutomator2 的资源 ID、文本和内容描述提取元素，鸿蒙从 UITest 布局提取属性和边界，iOS 从 XCUITest 的标识、label、value 和逻辑点边界提取元素。各适配器将边界映射到同一张全屏截图，按需叠加编号；模型看到的节点编号只在这一次观察内有效。

优先按唯一节点操作。自绘界面缺少节点时，可在任务允许的范围内用截图定位；若传给模型的是缩小图，适配器须先按该图尺寸还原位置，再映射到真机。受保护画面、元素遮挡或坐标对应关系不明时，返回缺失原因。截图和树之间发生旋转、前台 App 切换或布局移动时，重新采集。上下文通常只保留当前截图和近期动作摘要，遇到无进展再加入上一张图进行对照，首版无需常驻 OCR 或单独部署反思模型。

### 决定下一步与执行

1. 运行器把本次观察、设备支持的动作、尚未满足的条件和上一动作的实际结果发给模型。屏幕上的文字按应用内容处理，不能更改用户目标或扩大动作权限。
2. 模型每轮可提议一个基于当前观察的动作，也可提议完成或请求帮助。例如，`{"kind":"act","observationId":"o7","action":"tap","nodeId":"n12"}` 表示点击第七次观察中的节点。模型适配器将同一个手机工具声明为 OpenAI 的函数工具或 Anthropic 的自定义工具，并按调用 ID 回传实际结果。手机页面可能在每次点按后变化，首版每轮只接受一个设备动作；若模型一次调用多次，逐个回传未执行原因，再要求它基于当前观察选择一步。[OpenAI 自定义工具接入](https://developers.openai.com/api/docs/guides/tools-computer-use-integration) · [Anthropic 工具调用](https://platform.claude.com/docs/en/agents-and-tools/tool-use/how-tool-use-works)
3. 运行器核对观察时效、前台 App、动作参数与任务权限，再调用第 3 节的适配器。iOS 的返回动作必须能定位当前页面的导航控件；Android、鸿蒙可执行系统返回。受限任务只接受可辨认的导航目标，未识别位置和会改变蓝牙设置的控件均不可点按。
4. 每次动作发出后先观察实际结果，再决定下一步。超时且效果未知时按第 7 节结束，避免重复输入或提交。可重现的初始默认值为最多 20 轮决策、总计 120 秒；连续两次相同动作后的前台 App、可见控件与已满足条件均无变化时，记录无进展并交给用户。只读等待也占用总预算。

### 任务完成的证据

以“进入蓝牙页，再回到设置首页，保持开关原值”为例。从首页出发又回到首页，仅检查最后一张截图会让根本没离开首页的运行也通过。验证器把观察标记为准备、Agent 执行或事后核查。“到达目标”和“返回首页”只接受 Agent 执行阶段按顺序产生的观察，防止把验证器自己打开过的页面算作模型的成绩。

| 检查点 | 验证器直接核对的内容 |
| --- | --- |
| 起始状态 | 验收准备时读取蓝牙开关初值并回到设置首页，再交给模型。每个平台在验收机上固定可读的控件值或系统公开读数，记录读数来源 |
| 到达目标 | 在后续观察中同时识别系统设置 App 和蓝牙页独有的控件。首页里的“蓝牙”入口、搜索结果或显示相同标题的弹窗不能单独满足此条件 |
| 返回与保持原值 | 在更晚的观察中识别设置首页独有标记。检查动作记录中只有允许的导航操作，并复读蓝牙设置与初值比较。若复读需要进入子页，由验证器执行只读核查并恢复首页，随后再确认最终页面 |

全部条件满足才返回 `succeeded`；验证器可以在条件齐备时主动结束。模型提前提议完成时，返回缺失的条件，在剩余预算内继续。权限弹窗、受保护画面或缺少可信读数导致结果无法证实时，返回 `needs_review`；预算耗尽、协议错误或设备故障返回 `failed` 并保留具体原因。只有 `succeeded` 使用退出码 0。报告列出已满足和缺失的条件、对应观察编号、模型与驱动版本、决策轮数及耗时，即使未保存截图也能区分实际通过与未经验证。

## 7. 失败处理与数据

| 情况 | 工具行为 |
| --- | --- |
| 发现设备但控制会话无法启动 | `doctor` 分别报告连接、会话和观察接口的探测结果，给出下一步，例如确认 USB 授权或重新配置 WDA 签名。实际输入能力以真机动作和页面回读结果为准 |
| Android 设备未就绪 | 区分 ADB 的 `unauthorized`（等待机主确认）、`offline`（连接中断或无响应）以及设备在线但测试组件安装或启动失败。报告所用 SDK 路径、ADB 和驱动版本，方便复现 |
| 页面变化、元素缺失或重名 | 重新读取界面进行有界等待。到期或仍存在歧义时报告失败，调用者可以检查新截图和候选元素 |
| 点击或输入发出后断线、超时 | 报告 `ACTION_OUTCOME_UNKNOWN` 并停止脚本。重连后重新观察，由调用者决定从哪一步继续，避免重复提交或输入 |
| 锁屏、授权弹窗或受保护内容阻断任务 | 能识别原因时报告需要用户处理。原因未知时保留驱动错误；单张黑色截图不足以判定为受保护内容 |
| 用户中断脚本 | 停止调度下一步，结束本次会话，释放设备锁并清理临时文件。已发出的动作按实际结果报告 |

默认日志只记录步骤、耗时、错误码和工具版本。截图与控件树可能包含私人内容，仅在指定输出目录时保存。输入文本不写入日志，运行报告中的设备标识使用本次运行的别名。脚本动作通过固定接口传递；实现鸿蒙文本输入时必须处理设备端 shell 的参数边界，并用包含空格、引号的文本验证回读结果。

配置云模型时应显示接收数据的服务和所需输入（目标、屏幕画面、控件摘要）。运行器只发送已选任务与 App 范围内的观察；切换到未授权 App 或出现敏感输入界面时暂停外发并请求接管。协议失败和用户中断时仍执行会话清理。Agent 报告中的读数只保留任务声明的验证字段。

## 8. 实施顺序与发布验收

1. **验证三种真机连接。** 鸿蒙通过 HDC，iPhone 通过签名后的 WDA，Android 通过已授权的 ADB 和 UiAutomator2，各取得一张可解码 PNG 和一份可解析的控件树。Android 真机到位前可用模拟器开发适配器，发布记录须附真机结果。
2. **实现共同的动作。** 完成单步 CLI、定位与坐标换算，在三个平台验证点击、滑动、中英文输入和启动 App。采集验收页面的稳定标识和往返路径，建立设置导航映射。
3. **交付脚本与诊断。** 实现条件等待、明确的设备选择、错误报告和中断恢复。在三个平台的真机上运行同一任务，记录型号、系统构建和可复现的工具链组合。
4. **接入模型并验证完成判定。** 先用可回放的模型回复和设备观察检验过期节点、提前结束、重复动作及读数缺失，再用至少一种实际配置的模型在三台真机验证选定目标。两个厂商协议均作为设计参考，发行清单注明实际跑通的模型和版本。

| 发布验收项 | 三个平台的真机均须满足的通过条件 |
| --- | --- |
| 设置导航 | 简体中文环境，从约定的起始状态启动设置、打开蓝牙页、验证仅在目标页出现的控件、返回设置。连续 5 次通过，蓝牙开关状态保持原值 |
| Agent 真机任务 | 每个平台用同一蓝牙目标连续运行 5 次，每次独立绑定初值、到达和返回证据。按平台记录通过次数、总耗时和模型调用次数，报告附具体失败步骤。通过要求为每平台 5/5 |
| Agent 误判与恢复 | 回放仅有首页却提议完成、仅在准备阶段出现目标页、旋转后点击旧节点、连续无进展、动作结果未知及缺少蓝牙读数的样例。误报成功为 0；旧节点不点击，结果未知的动作不重发，预算内结束 |
| 基础输入与定位 | 在可回读的测试输入框分别输入英文、中文及含空格和引号的文本，逐字核对。验证按控件点按和滑动；在支持旋转的测试页验证横竖屏坐标 |
| 真机异常 | 在授权缺失、设备断开、目标缺失或重名时给出对应原因。断线后重新连接可以启动新会话，结果未知的写操作不会被自动重发 |
| 设备选择与诊断 | 三个平台的手机同时连接时，依次指定一台执行操作，另外两台页面保持原状。同一台手机被另一个运行占用时，第二个调用收到明确的忙碌状态 |
| 安装与结果复核 | 按发布说明从干净的主机配置建立会话。记录型号、系统构建、工具链、首次启动耗时和热会话截图耗时。未通过的必选项阻止 1.0 发布 |

首版发布物包括 CLI、三个平台的接入指南、蓝牙导航脚本与对应的 Agent 任务定义，以及三个平台的真机验收记录。升级设备系统或驱动后重跑真机验收；升级模型或修改任务提示后重跑 Agent 回放与真机任务，再更新支持清单。
