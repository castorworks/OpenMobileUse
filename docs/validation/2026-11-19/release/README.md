# 1.0 三端验收记录

2026-11-19 在鸿蒙 BRA-AL00、iPhone 13 和 Android 15 模拟器上完成以下实测。两台手机通过 USB 连接。Android 正式发布所需的厂商真机仍待接入。

| 设备 | 简体中文蓝牙脚本 | 默认 Agent 蓝牙导航 | 模型请求数 / 五轮耗时 | 通用设置搜索 | 视觉搜索 |
| --- | ---: | ---: | ---: | ---: | ---: |
| [鸿蒙 BRA-AL00](harmony.json) | 5/5 | 5/5 | 11 / 226.2 秒 | 通过 | 通过 |
| [iPhone 13](ios.json) | 5/5 | 5/5 | 10 / 239.5 秒 | 通过 | 通过 |
| [Android 15 模拟器](android.json) | 5/5 | 5/5 | 30 / 173.8 秒 | 通过 | 通过 |

离线脚本和默认 Agent 每轮都确认已到达蓝牙页、开关与初值相同、最终回到设置首页。三台设备的初值均为开启。五轮 Agent 耗时包含基线、模型决策、驱动操作和独立复查。三个平台的请求和服务回复模型 ID 均为 `deepseek-flash`，端点为 `https://api.deepseek.com`。每台设备的 JSON 保留逐轮读数、模型请求数和检查点。

iPhone 13 在 iOS 18.7.7 上通过启动参数为设置 App 选择简体中文，整机语言保持英文。首次脚本运行在基线阶段失败。控件树同时给出英文导航栏标识 `Bluetooth`、中文开关和中文返回按钮。修正匹配后重新开始计数，连续通过五轮。

通用脚本在三端输入「蓝牙」、等待搜索结果、返回并验证搜索界面消失和首页入口可见。视觉任务允许模型查看设置搜索入口的裁剪图。三端都实际调用了 `request_view` 和 `tap_visual`，通过主机检查点，并在新的 `inspect` 会话再次读到搜索页控件。[通用脚本](../../../../examples/settings-search.json) · [视觉任务用法](../../../../README.md#用-agent-自主导航)

## 故障与设备选择

| 场景 | 结果 |
| --- | --- |
| 同设备争用和中断 | 三端在脚本等待期间启动第二个进程，收到 `DEVICE_BUSY`。向运行中的脚本发送 SIGINT 后只记录首步，结果为 `CANCELLED`。随后都能建立新会话。 |
| 点击回执丢失 | 三端分别向真实驱动转发一次点击，确认驱动执行后丢弃回复。调用返回 `ACTION_OUTCOME_UNKNOWN`，下次 `doctor` 同时读到一条未决点击和实际到达的新页面。此项使用桥接故障注入。 |
| 两台真机的 USB 中断和恢复 | 鸿蒙从 HDC 列表消失，诊断为 `DEVICE_UNAVAILABLE`。重新接线并开启、授权 USB 调试后，新会话取得前台观察。iPhone 拔线后仍被 Xcode 枚举为网络设备，WDA 报未知目标。重新接线后，`doctor` 经 USB 读到前台应用。已加入 WDA 原始错误的分类回归。 |
| Android 调试授权 | 在另一个启用安全 ADB 的 API 28 Google Play 模拟器上，以全新客户端身份连接。实际 ADB 的 `unauthorized` 和 `offline` 分别产生 `AUTHORIZATION_REQUIRED` 和 `DEVICE_OFFLINE`。通过系统授权弹窗后，同一客户端成功回读 API 级别。 |
| 定位错误 | 三端均对不存在的控件返回 `WAIT_TIMEOUT`，对重名控件返回 `AMBIGUOUS_ELEMENT`。鸿蒙在设置搜索结果中测重名，iOS 和 Android 在设置首页测重名。 |
| 三端同时在线 | 依次指定一台，由 CLI 启动 iPhone 计算器、鸿蒙计算器或 Android 时钟。每次并发读取三台设备，确认目标应用在前台、另外两台均在原设置首页，随后恢复目标设备。 |

## 隔离安装与耗时

按本轮约定使用同一台 Mac。新建项目目录，复制源码、测试和锁文件，使用空 npm 缓存运行 `npm ci`，独立构建并运行测试，再从该目录启动新的 Appium 服务并使用独立设备状态目录。沿用了 Mac 已安装的 SDK、Xcode、本机签名身份与手机既有信任关系。复现环境为 macOS 26.7.3（25G342）、Node.js 22.22.1、npm 10.9.4、Xcode 27.2（27B52）和 Appium 3.9.1。Android SDK 的 ADB 为 37.0.0，UiAutomator2 为 8.7.3。XCUITest 为 12.22.8。HDC 为 3.2.0d，UITest 为 7.0.0.1。

| 设备 | 新建会话 | 首次读取页面 | 同会话连续三次读取 PNG |
| --- | ---: | ---: | --- |
| 鸿蒙 BRA-AL00 | <1 ms | 2066 ms | 802 / 775 / 761 ms |
| iPhone 13 | 28068 ms | 2832 ms | 190 / 125 / 122 ms |
| Android 15 模拟器 | 1576 ms | 124 ms | 58 / 15 / 14 ms |

计时从新实例打开目标适配器开始。鸿蒙适配器在首次读页面时才调用 HDC。截图耗时包括驱动读取和数据传输。手机已有 WDA 和测试组件，表中数据仅代表本次安装条件。首次尝试与另一个 Appium 服务共用 WDA 默认端口时遇到占用，独立服务配置空闲的 `OMU_WDA_PORT` 后通过。

本次项目与隔离目录均通过全部 36 项自动化测试，覆盖客户端重试、截断回复、过期观察、误报完成、坐标换算及进程被 SIGKILL 后未决动作只保留一次。物理手机撤销既有主机信任后的首次配对未在本轮执行。原有单步和启动 App 的三端逐项记录可分别复核。[单步记录](../../../../README.md#单步验证记录) · [启动记录](../../../../README.md#启动指定-app)
